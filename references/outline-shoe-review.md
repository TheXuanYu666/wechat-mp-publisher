## 图片方案（重要，不是 17 张实拍）

发布页共 17 个 `<img>`，但只有 **5 个不同 URL**：

- **实拍图 4 张**：01/02/03/04 每节开头各一张（05、06 没有实拍）
- **装饰条 1 张，重复 13 次**：每个子标题**前面**都有一张，13 张 = 13 个子标题。这是账号固定素材，两篇跑鞋复用同一个 mmbiz URL，已存在 `template_rdfz.json` 的 `deco_image_url`

`render_template.py` 会**自动**在每个 `sub` 前插装饰条，写稿时不用管。已验证渲染出的图片序列与历史文章逐位一致：
`P P D D P D D D P D D D D D D D D`

所以每篇只需要准备 **4 张实拍图**，素材盘每款鞋 4–7 张正好够用，用 `collect_assets.py` 挑。

## 01 开篇简介：固定 5 字段，顺序不变

```
测评鞋款：{品牌 型号}
产品定位：{一句话定位}
官方发售价：¥{价格}
二级平台价格：¥{低}～¥{高}
实测重量：男款 {码数} 码，单只 {重量} g
```

`二级平台价格` 就是得物区间，全角波浪号 `～` 连接，联名/限定不计入（见 `dewu-pricing.md`）。历史值：`¥500～¥1000`、`￥229～￥869`、`¥600～¥1200`。

## 各节写法

**02**：子标题下用 `1.xxx：` `2.xxx：` `3.xxx：` 编号分点。跑鞋鞋面固定三点：材质与科技 / 透气性 / 做工细节。后跟与鞋舌写一段连续文字。

**03**：核心技术一段；脚感描述固定 5 点 `1.缓冲/缓震 2.中底厚度与落差 3.回弹/反馈 4.稳定性 5.舒适性`；不同场景表现跑鞋固定 3 点 `1. 慢跑 2. 节奏跑/速度训练 3. 长距离`。

**04**：材质与设计 / 抓地力 / 耐磨性各一段，耐磨性给预估寿命公里数。

**05**：三行不带编号 `尺码建议：` `鞋楦宽度：` `舒适性缺陷：`

**06**：优点、缺点各 3–4 条 `1.` 起编号；适用人群两行 `非常适合：` `不太适合：`；评分；结论一段。

### 评分维度两个栏目不一样

跑鞋篇 **5 项**，写法 `X/10`：

```
缓震/回弹：8/10
稳定/支撑：9/10
抓地/防滑：8/10
舒适/合脚：7/10
耐久/耐磨：9/10
综合得分：8.2/10
```

篮球鞋篇 **7 项**，写法 `X 分`：

```
缓震：8.5 分
反馈：9 分
包裹：8.5 分
支撑：9 分
抓地：8 分
耐磨：8 分
重量：8分
综合得分：8.4 分
```

## 文末固定块（顺序照抄，只换人名日期）

```
注：本社与品牌无利益关联，所有观点独立客观。脚感因人而异，请理性参考。
测评人：{测评人}
编辑：{测评人}
发布日期：{YYYY年M月D日}
本文为「RDFZ 步界社」原创测评，未经许可，请勿转载。
```

**「审核」那一行已按用户要求删除**（历史文章里有，新稿不再输出）。默认署名见
`references/footer_defaults.json`：测评人和编辑都写{测评人}，发布日期每篇按实际填。

机制上：`render_template.py` 会把值为空的署名字段**整行删掉**，所以 `footer.reviewers`
留空就自动没有「审核」这一行，不需要改模板。渲染报告里的 `footer_lines_dropped`
会列出被删掉的行，便于核对。

## 行内强调有语义

- 蓝 `rgb(95, 156, 239)`：正面结论 → 写作时用 `**文字**`
- 橙 `rgb(249, 110, 87)`：短板、负面 → 写作时用 `~~文字~~`

一段强调 2–4 个短语，只强调结论性短句，不强调整句。历史每篇蓝 30–37 处、橙 9–13 处。
