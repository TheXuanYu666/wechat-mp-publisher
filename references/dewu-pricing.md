# 得物二级市场取价规则

二级市场统一指**得物**。目标是给出"正常人买这双鞋大概花多少"，不是罗列全部 SKU。

## 价格从哪来：App 截图 + 本机 OCR

### 为什么不抓网页（已实测）

| 检查 | 结果 |
|---|---|
| `dewu.com` 桌面站（JS 渲染后） | 可见文本 997 字，全是导航/页脚/下载 App，无商品无价格 |
| `/`、`/search?title=…`、`/spu/12345` | 返回**完全相同**的页面 |
| 商品接口 `app.dewu.com/api/v1/h5/commodity-pick-interfaces/pc/…` | HTTP **485**（签名/风控拒绝） |
| `m.dewu.com` | HTTP **502** |

结论：得物没在网页端开放商品数据，登录也没用。绕签名直连 App 接口属于绕风控，不做。

### 主路径：截图识价

用户在得物 App 里截配色/价格列表 → 图片放到 Mac → 本机 Vision 离线 OCR：

```bash
python scripts/dewu_ocr.py --dir ~/Desktop/dewu截图 --shoe "飞燃3" \
  --out tmp/dewu_clean.json --dump tmp/ocr.json
```

配对逻辑：每个 `¥价格` 依次尝试「同一文本块内」→「同一行邻近块」→「上方最近一行」找配色名；
都找不到就记进 `orphans`，不会硬凑。噪声词（已鉴别、包邮、尺码、销量、US/EU 码等）会被排除。

识别结果**必须和截图核对**后才能进文章。

### 兜底：直接报文字

```
黑白 829
全黑,845
白蓝 ¥798
```

```bash
python scripts/dewu_prices.py filter --shoe "飞燃3" --out tmp/dewu_clean.json --text "<上面这些行>"
```

## 清洗（filter）

顺序执行：

1. **同配色取最低价** —— 一个配色多个尺码/渠道时只留最低价
2. **关键词剔除** —— 名称命中 `联名|联乘|限定|限量|抽签|定制|复刻|纪念|艺术家|合作款|礼盒|套装|OFF-WHITE|Sacai|Travis|Fragment|Union|Undefeated|Collab` 直接省略
3. **离群剔除** —— 以剩余配色价格的中位数为基准，`> 中位 × 1.8` 或 `< 中位 × 0.55` 省略
4. 低于 `--min-price`（默认 100 元）的直接丢，通常是抓错字段

例：大部分配色 780–860，中位 820 → 上界 1476、下界 451。某联名 4200 元先被关键词命中，即使漏了也会被离群规则拦掉；某"399 元"如果是抓到了配件价格，会被下界拦掉。

倍数可调：`--high-mult` / `--low-mult`。改动了就要在文章或交付说明里讲清口径。

## 写进文章

- 只给**主流配色区间**：`stats.mainstream_range`，例如"主流配色 780–860 元"
- 表格最多列 4–6 个配色，按价格升序，附采集日期
- 必须写"截至 YYYY-MM-DD，得物平台售价，随行就市"
- 被省略的联名/限定**不提、不暗示、不写"另有高价配色"**
- 不写"最低价""史低""稳赚""必涨"，不做任何投资/转售收益暗示
- 得物价含平台服务费与否要按页面实际口径说明，不确定就只写"页面显示价"

## claims 登记

每个进文章的价格都要一条 claim：

```json
{ "id": "p_black", "subject": "Nike Vomero 18", "metric": "得物二级市场价（黑白配色）",
  "value": "829元",
  "sources": [{ "title": "得物商品页", "url": "https://www.dewu.com/spu/...",
                "quote": "¥829 起", "date": "2026-08-30" }] }
```

价格类 claim 允许单一来源（得物本身就是唯一口径），但 `date` 必填，且 `metric` 里要带"得物"或"二级"字样，否则 `fact_check.py` 会提示来源不是得物。
